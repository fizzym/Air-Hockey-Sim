1Overview

The trainer owns the clock. The simulator only knows how to move every game forward by a given amount of time.

2Simulator state

Every quantity has a leading game axis, so one NumPy call updates every game at once.

3Mallet model

Each axis of the Core-XY gantry follows a third-order linear model, so its position has an exact formula for any constant voltage.

Six constants a1 a2 a3 b1 b2 b3 describe the motors. Because a Core-XY belt drives the x axis with (a − b) and the y axis with (a + b), the code builds per-axis coefficients C5 C6 C7 from those sums and differences. The characteristic roots ab and the coefficient table CE then give position as A·eat + B·ebt + C·t + D.

Turning an action into a trajectory

An action is a target point x_f and a voltage Vo for each axis. update_path reads the mallet's current position, velocity and acceleration at the current time and folds them into the initial-condition terms C2–C4. The voltage becomes C1. If the mallet would overshoot, the voltage sign is flipped. solve_a() then uses Newton's method to find the switch time of a bang-bang profile (full voltage one way, then the other) that brings the mallet to rest at x_f.

Note the last line: the simulator's clock is time since the last action, which is why the trainer passes it only the time to the next event.

4Puck model

Between collisions the puck moves in a straight line, slowed by friction and air drag: m·v̇ = −f − B·v².

That equation has an exact solution. Distance travelled is a log-cosine and speed is a tangent, both in terms of an integration constant C set from the starting speed. The puck stops at t = −C·m, and the functions clamp there so a stopped puck stays stopped.

Air_hockey_sim_vectorized.py:269–295closed-form puck distance and speed
def dP(t, B, f, mass, C, D):
    tpZero = get_tPZero(mass,C)
    t = np.minimum(tpZero, t)
    p = (mass/B) * np.log(np.cos((np.sqrt(B*f)*(C*mass+t))/mass)) + D
    return p

def velocity(t, B, f, mass, C):
    tpZero = get_tPZero(mass,C)
    v = np.zeros_like(t)
    v_mask = t < tpZero
    v[v_mask] = -np.sqrt(f/B)[v_mask] * np.tan(((np.sqrt(B*f)*(C*mass+t))/mass)[v_mask])
    return v
...
def get_tPZero(mass, C):
    return -C*mass

def getC(v_norm, B, f):
    return - np.arctan(v_norm * np.sqrt(B/f)) / np.sqrt(B*f)

def getD(B, mass, f, C):
    return - (mass/B) * np.log(np.cos(np.sqrt(B*f)*C))

Wall hits

update_puck computes the straight-line distance s to the nearest wall. If the puck would travel farther than s in the time left, that game has a wall hit. The exact hit time is found by the Chandrupatla root finder on distance_to_wall. The puck is moved to the wall, its normal velocity is reversed and scaled, and the unused time is returned so the game is advanced again.

The learned collision networks (HeteroscedasticNN) are still defined in initalize, but the lines that load and call them are commented out, so every bounce uses the fixed restitution factor.

Ending a game

check_goal() returns masks of games where the puck went past either end. check_state() returns the indices of games in an invalid state: puck off the table outside a goal, or puck overlapping a mallet. Both set reset_mask so those games stop moving until the trainer calls reset_sim. Separately, impulse() nudges slow pucks (under 0.15 m/s) toward a randomly drifting point, so a puck never sits perfectly still.

    global reset_mask

    entered_right_goal_mask = np.logical_and(puck_pos[:,0] > surface[0], np.logical_not(reset_mask))

    entered_goal = (entered_left_goal_mask | entered_right_goal_mask)

    if np.any(entered_goal):
        reset_mask = reset_mask | entered_goal

6Sensing and timing

The trainer reproduces the real robot's timing: what the policy sees is late and noisy, and the mallet reacts late too.

Three event streams run side by side. A camera frame arrives every 1/119.96 s. An action is taken about 13.4 ms after the frame it is based on (image processing delay). The mallet state the policy sees is sampled 4.6–7.7 ms before the action. Only every other frame triggers an action (inference_img alternates), which gives the 60 Hz control rate. The scheduler always advances the simulator to whichever event is soonest.

Camera noise

Each camera frame stores the puck and opponent mallet positions with several layers of error, all calibrated against the real camera:

Fixed lens distortion

A low-frequency Perlin noise map (std 1.2 mm), sampled at an offset unique to each game. The same spot on the table always reads slightly wrong in the same way.

Frame-to-frame jitter

Gaussian noise whose standard deviation grows linearly with distance from the camera (puck_std).

Gantry beam occlusion

When the gantry beam is between the camera and the puck, noise is larger (puck_beam_std), and a fraction of frames (percent_miss) just repeat the last reading.

Mirror augmentation

Before each decision, a random half of the rows are flipped top-to-bottom with apply_symmetry. The policy acts on the flipped view and the y target is flipped back. This teaches the policy that the table is symmetric.

Networks

The attacker and defender each have a policy network and two Q networks of the same shape (39 → 512 → 256 → 128 → 64, LayerNorm on the first two layers, LeakyReLU). The policy ends in 10 outputs: a mean and a scale for each of the 5 actions.

Domain randomization

Motor constants

Drawn per game and per player from ab_ranges, scaled by a random speed factor of 0.7–1.2. One time in five the measured real values are used instead. Redrawn on every reset.

Voltage noise

Gaussian noise (std 0.07 V) on each commanded voltage.

10SAC update

A hand-written Soft Actor-Critic step, run separately for the attacker (i = 0) and the defender (i = 1).

torchRL_Training_SAC.py:331–411update_sac_agent() (comments trimmed)
def update_sac_agent(i, batch_size, gamma=0.99, tau=0.005):
    # Select components for agent i
    if i == 0:
        buffer = policy_buffer
    elif i == 1:
        buffer = def_buffer

    actor = policy_modules[i]
    q1, q2 = Q_modules[2*i], Q_modules[2*i+1]
    t_q1, t_q2 = Q_modules_target[2*i], Q_modules_target[2*i+1]
    log_alpha = log_alphas[i]

    batch, info = buffer.sample(batch_size, return_info=True)
    batch = batch.to(DEVICE)
    next_batch = batch.get("next")

    # --- 1. Critic Update ---
    with torch.no_grad():
        actor(next_batch)

        next_log_prob = torch.clamp(next_batch.get("action_log_prob"), -7, 100)
        ...
        target_q1 = t_q1(next_batch).get("q_value")
        target_q2 = t_q2(next_batch).get("q_value")

        alpha = log_alpha.exp()
        target_q = torch.min(target_q1, target_q2) - (alpha * next_log_prob)[:,None]
        y = next_batch.get("reward") + (1 - next_batch.get("done").float()) * gamma * target_q

    q1_val = q1(batch).get("q_value")
    q2_val = q2(batch).get("q_value")
    q_loss = nn.functional.mse_loss(q1_val, y) + nn.functional.mse_loss(q2_val, y)
    ...
    actor_td = actor(batch)
    log_prob = torch.clamp(actor_td.get("action_log_prob"), -7, 100)

    q1_pi = q1(actor_td).get("q_value")
    q2_pi = q2(actor_td).get("q_value")
    min_q_pi = torch.min(q1_pi, q2_pi)
    ...
    policy_loss = (alpha.detach() * log_prob - min_q_pi).mean()
    ...
    alpha_loss = -(log_alpha * (log_prob + target_entropy[i]).detach()).mean()

The function's default gamma and tau are overridden by the call, which passes the module values gamma = 0.98 and tau = 0.001. Target entropies are −6 for the attacker and −4 for the defender, and both temperatures start at log α = −5.5.

12Known issues

Things found while reading the code for this page.

Training stops after 900 actions. The training loop calls sim.display_state(envs-10) once per action, and that function writes a video frame and then deliberately raises an error once it has written 900 frames (15 s of video at 60 fps). With 10 actions per round, that is round 90, so only the round-50 checkpoint is ever saved.
